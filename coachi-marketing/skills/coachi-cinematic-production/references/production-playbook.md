# Production and finish gates

## Before paid calls

First confirm an **approved production brief**, not only an idea, estimate or provider balance. Strategy is collaborative; production is autonomous after the meaningful details are locked or intentionally delegated. Record the approval source/version and verify there are no unresolved material choices. Do not ask for the same approved strategy again. If no strategy exists, complete and agree it before submitting paid production.

Read the current campaign entrypoint, shot/source records and budget—not every historical revision. Copy/adapt the brief template only when it saves work; existing equivalent JSON/specs remain authoritative. Record:

- concept/platform/viewer problem; current authorized outcome (plan, local film, revision or launch);
- runtime target and locked elements; exact current capture exceptions and reference-use rights;
- approved providers/credential source (never the value), per-ad total allowance, incurred/uncertain reservations and remaining headroom;
- reusable approved assets, missing shots and a local fallback for each fragile action.

Use current account/model documentation or official read-only capability checks for availability, input roles and price; a model name, balance or regional console from an older job is not current access. User preference is Image2references and BytePlus/Seedance motion. If the available image tool cannot guarantee Image2, do not silently change it. Follow that tool/skill's supported route; explain a real capability blocker once.

Reserve the expected maximum for a request before submitting; no cumulative reservation beyond the explicit cap. Uncertain cost stays reserved until reconciled. An estimate or wallet top-up is not a new allowance. Budget for a coherent complete cut with a repair reserve instead of spending everything on decorative options. Reuse accepted takes before generating alternatives.

Persist request intent, provider, current model/settings, source hash, prompt version, operation ID and result status. An accepted or ambiguous job is reconciled/polled by its existing ID; never resubmit just because a wait was interrupted. Known pre-request failure differs from a possible accepted request. Stop paid work on cap exhaustion or an unresolved policy/access block; continue safe local work. Do not evade provider privacy rejection by changing keys, encoding or prompt. Legitimate authorized reference changes still must obey the provider's rules.

Do not expose keys, bearer links or private app/location data in prompts/logs. A supplied screenshot permits scoped task use, not every new external destination. Prefer a blank synthetic handset guide for generated hand plates and keep genuine UI compositing local. If a necessary source transmission lacks authority, ask exactly about that data/destination, not a vague “continue?”.

## Asset and shot preparation

Inventory by role: identity/wardrobe; route/world; action coverage; real native UI; watch/integration proof; performance cues; cleared music; brand/store marks. For selected sources retain path, hash, dimensions, source timecode/date, rights/privacy and status. Inspect actual pixels and motion; filename or successful download is not quality proof.

Source priority for product proof is the appropriate genuine user capture, then a clearly identified native simulator/AppStore/source-grounded demonstration if authorized. AppStore marketing posters are useful visual references, not raw interactive UI. Do not substitute Android for iOS or upscale low-detail source and call it native1080p. Keep applicable date/build requirements; the specifically supplied September7captures had bounded approval, not an exemption for all later media.

Write each shot as: **start state -> action -> end state**, camera/scale/motion, duration/handles, identity/gear, lighting/terrain and screen/cue timing. Plan actual distinct coverage. A still cannot prove a button tap, light switch, wrist raise or gait. Match start/end/reference conditioning to supported provider controls; do not use featureless black as the only identity reference for a headlamp scene.

Generate/inspect one high-risk reference or motion proof before scaling the agreed look. Under the approved production brief this is internal QA, not automatically another user approval. Keep reference prompts free of generated UI lettering/numbers; screen text, typography and exact black frames belong in deterministic local editing. Separate identities/background references from the actual recorded app data.

## Native phone and watch integration

Use the existing native-source validator, phone compositor/Blender and editor path; do not bypass source gates. Inspect the original source at the exact selected timestamps. Keep display density, correct perspective/rounded glass, occlusion, grip and phone size. Readability at roughly360px-wide viewing and native close inspection are both required checks, not proof of native interactivity.

For gestures verify **before -> contact -> state change**. Do not confuse warmup's START NOW with initial session creation, countdown expiry with a finger tap, Pause with End, or app pause with music pause. Never let a static screenshot silently assert a native transition. A source-grounded editorial demo may be usable if clearly presented and allowed by the brief.

Reuse the coherent continuous-time camera from the existing compositor for rhythmic phones; do not independently animate the screen. Check no drift, out-of-frame borders, clipped UI, frozen/reset movement or tap pulse left on screen after the cut. Render one readable proof before all setup states.

For a watch, match visible casing/dial orientation to the actual physical bezel and track the glass through motion. Check for key-color residue and drifting reflections. Keep the natural wrist glance. Preserve numeric meanings: current versus average pace, timer direction, work versus rest, rep count and time before acceleration. Show unavailable values honestly or use explicitly approved, visibly disclosed example data. Never transplant resting HR or another person's route/result into a generated athlete's claimed live session; a visible Garmin belt/watch is not integration proof.

## Audio-first timing

Select the exact Performance Mode phrase/take from its manifest/path/hash. Listen before final assembly. An identically named default voice file is not interchangeable. Reuse the accepted natural take; do not force synthetic intra-word pauses or compress a full cue into a short shot. Any new TTS call needs the applicable budget/voice authority.

Measure actual cue durations. Place full cues and duck envelopes on the shot timeline; ensure warning -> reaction -> confirmation and rest -> complete Start -> acceleration. A compressed interval story is not a literal elapsed-time demonstration. UI/countdown/speech/action must make the same promise.

Use a paid-ad-cleared/owned track with a saved licence/source and permitted platform/territory where relevant. Availability on a consumer music service or in a user's recording is not ad clearance. If rights are unknown, choose another already cleared source or mark a draft; do not publish on an assumption.

Build music/voice stems and a full-duration mix. Mute all other audio unless the current brief explicitly changes the music-and-coaching-only policy. Use smooth cue ducking and recover energy between phrases. Starting mix references around−14to−16LUFS and peak headroom of at least1dB are house QA heuristics, not a TikTok requirement; listening and current destination specs govern. Measure clipping/true peak, cue endings and the last seconds after any trim, offset, extension or music replacement.

For picture-only revisions retain the exact approved audio stream when technically possible and verify AAC payload identity. Do not recast the voice or remix chosen music while fixing a nose, phone or cover. Music-comparison variants keep one picture/voice/timing master and differ only in music arrangement/mix; verify every variant end-to-end.

Preserved picture content is not necessarily byte-identical encoded video: a re-encode can alter packets and nearby decoded pixels. Verify unchanged shot content, timing and intended processing separately, compare against an appropriate re-encode baseline if exact pixel differences matter, and never claim whole-picture identity from matching AAC hashes.

## Final acceptance checklist

Use PASS / NEEDS FIX / NOT VERIFIED with concrete evidence. Do not replace review with a generic score or claim10×quality from tests.

| Gate | Observable check |
| --- | --- |
| Early meaning | First few seconds make Coachi's role apparent without prohibited copy; one viewer benefit is identifiable. |
| Story/causality | Viewer can follow setup, guidance, response and payoff; no contradictory intensity, false instant HR result or confusing timer. |
| Coverage/continuity | Real wide/medium/detail/POV variation, spatial progression, no duplicate source handles masquerading as new journey, no dead/frozen tails. |
| Identity/action | Consistent face/body/wardrobe/dog/gear; natural smile/skin/nose; credible gait, fingers and requested gesture. |
| Device truth | Right platform/build/source, readable UI, actual button/state, correct projection and data provenance; no drifting glass/green edge. |
| Voice and music | Correct mode/take, natural intact speech, reaction time, intelligible mix, only approved audio, cleared rights and music through final frame. |
| Ending | In-scene brand and permitted CTA readable long enough; no unrelated late shot or abrupt black/music cutoff. |
| Encoded file | Full decode, expected frame count/duration,1080×1920delivery, documented source resolution, appropriate frame rate/BT709/H264/AAC or current required preset. No technical tag claim without checking it. |
| Whole-film playback | View/listen to the encoded final at normal speed, including all joins and ending, and inspect key native-detail frames. Record what actually played and any phone-speaker limitation. |
| Handoff | Versioned final/spec, hashes/source references, reservations versus settled spend, excluded placeholders/rejected sources and explicit status. |
| Brief fidelity | Final shot/story/product/audio/ending match the approved strategy; any material deviation is separately resolved, not silently redesigned. |

Sampled contact sheets are for diagnosis; they do not prove continuous motion or subjective audio. If normal-speed playback is unavailable, deliver as a technically/sample-checked review cut with that limitation, not an unqualified fully reviewed final. Low-quality generated footage remains low quality even if1080p export checks pass.

For a failure, correct the narrowest causative component and recheck downstream output. If feedback changes a concept, update active shot/audio rows and current entrypoint, preserve but exclude superseded assets. Stop further paid iterations at the cap; a clearly stated blocker/review cut is better than claiming final with hidden placeholders. Final user preference remains separate from the agent's QA judgement.

## Launch is separate

When explicitly asked to upload/activate, prefer the available Coachi TikTok launch checklist; otherwise read the current launch record and official API contract. Use **official TikTok Ads API, never Pipeboard**. Reconcile the exact approved MP4 hash, account/identity, app/event, audience, budget and end before writing. Do not bake old campaign IDs, markets, allowances or credits into a future default.

Creation approval is not publication or media-spend approval. For an authorized same-campaign creative addition, keep existing campaign/group controls and original ad unchanged, verify import, create new ads disabled, read back and then enable only the approved new IDs. AI disclosure and music rights remain launch gates. Any additional temporary private storage destination requires its own valid source-use authority; use short-lived links and remove only task-owned temporary objects after verified import. Never expose a bucket or secret to avoid a transfer limitation.

Distinguish uploaded, created, enabled, in review, eligible, delivering and attributed results. TikTok optimized delivery is not guaranteed equal rotation or a randomized test. New films/captions are creative treatments; compare a common actual delivery window and cost per the selected conversion event, with delayed iOS attribution explicit. No automatic monitor or budget expansion unless requested.
